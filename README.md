# A Stochastic Framework for Quantifying Cryptographic Assurance in Post-Quantum Migration

Code released alongside the paper *"A Stochastic Framework for Quantifying
Cryptographic Assurance in Post-Quantum Migration"* (Athar, Moiz, ul Hassan,
Khan, Shah — Department of Cyber Security, National Cyber Security Academy,
Air University, Islamabad).

This repository contains the complete Monte Carlo simulation framework used
to produce every numeric result, table, and figure reported in the paper:
the Residual Quantum Risk (RQR) evolution figures, the Composite Assurance
Score (CAS) trajectories, the Trust Continuity Index (TCI) summary table,
the sensitivity analysis (tornado chart + heatmap), and the convergence
sweep. All results are exactly reproducible from a fixed random seed.

## What this framework models

Public-key cryptography deployed today (RSA, ECC) is vulnerable to a
sufficiently capable quantum computer running Shor's algorithm. This
framework turns that qualitative risk into a trackable, simulate-able
quantity by chaining together four subsystems:

1. **Adversarial capability growth** — a stochastic model of how fast a
   quantum adversary's capability grows year over year, calibrated against
   real survey data (Global Risk Institute / evolutionQ 2024).
2. **Residual Quantum Risk (RQR)** — a logistic function mapping the gap
   between adversarial capability and a cryptographic algorithm's quantum
   attack cost onto a break probability.
3. **Composite Assurance Score (CAS)** — a weighted combination of
   algorithm strength, key management posture, deployment coverage, and
   crypto-agility.
4. **Trust Continuity Index (TCI)** — the multi-year mean of CAS, used to
   compare migration strategies (aggressive / conservative / late-start).

All four subsystems are propagated through a vectorized NumPy Monte Carlo
simulation (no per-year Python loops) so that uncertainty in each input
parameter shows up as a distribution over the output, not a single point
estimate.

## Repository structure

```
config.py            Central configuration: Monte Carlo settings, growth-rate
                      distribution parameters, CAS weights, attack-cost table.
simulation.py         Core Monte Carlo engine (capability growth -> gap ->
                      RQR -> CAS -> TCI). All array-vectorized.
scenarios.py          The three deployment-coverage curves L(t): Aggressive
                      (logistic), Conservative (linear), Late Start (delayed
                      linear).
sensitivity.py         Sensitivity-sweep utilities (growth-rate mean, alpha,
                      CAS weight w_AS) plus the 2D (mu_g, w_AS) heatmap grid.
main.py               Entry point. Runs the full simulation, writes the
                      results table, generates the RQR-evolution and
                      CAS-trajectory figures, and captures the computational
                      environment for the paper's reproducibility section.
run_sensitivity.py     Runs the sensitivity analysis: 1D sweeps, the tornado
                      chart, and the joint heatmap.
convergence.py         Dedicated Monte Carlo convergence sweep (N from 100 to
                      10,000) with a stated numerical tolerance, superseding
                      the quick eyeball check inside main.py.
```

There is no `output/` folder in this repository — it is generated by
running the scripts below, and is excluded via `.gitignore` so the
repository never goes out of sync with the code that produces it.

If a `paper_figures/` folder is present, it contains only the exact PNGs
cited in `main.tex`, included for reviewer convenience so the paper's
figures can be inspected without running any code first. It is not a
substitute for reproducing the results yourself.

## Requirements

- Python 3.9+ (tested on 3.14.7 and 3.11)
- See `requirements.txt` for exact packages. `psutil` is optional — if
  absent, `main.py` still runs but reports total RAM / core counts as
  "unavailable" in the environment report instead of raising an error.

Install with:

```bash
pip install -r requirements.txt
```

## How to run

Run these in order from the repository root. Each script creates or reuses
an `output/` directory next to the scripts.

### 1. Core simulation

```bash
python main.py
```

Produces, under `./output/`:

- `results_summary.csv` — mean RQR at Year 5 and Year 15 (and the 95th
  percentile at Year 15) for every algorithm in `config.SIMULATION_TARGETS`,
  plus TCI mean/std for every deployment scenario.
- `fig_rqr_evolution.png` — RQR over the 15-year horizon, mean line + 95%
  empirical band, one line per algorithm.
- `fig_cas_trajectories.png` — CAS over time, mean + band, one line per
  deployment scenario, with the CAS_min reference line.
- `environment_report.txt` / `environment_report.json` — the actual
  hardware/software environment the run executed on (platform string,
  processor, package versions, RAM, core counts, measured wall-clock time).
  This is what belongs in the paper's Computational Environment section —
  regenerate it on your own machine before submission rather than reusing
  a value produced elsewhere (including a cloud sandbox used only for
  development).
- A quick convergence eyeball check is also printed to the console
  (N = 100 to 1000). For the full convergence analysis with a stated
  tolerance, run `convergence.py` (below).

### 2. Sensitivity analysis

```bash
python run_sensitivity.py
```

Produces, under `./output/`:

- `sensitivity_mu_g.csv`, `sensitivity_alpha.csv`, `sensitivity_w_as.csv` —
  full 1D sweep output for each parameter.
- `sensitivity_summary.csv` — the tornado-style summary table (range
  tested, TCI range, ΔTCI) reported directly in the paper's sensitivity
  table.
- `fig_sensitivity_tornado.png` — horizontal bar chart of ΔTCI per
  parameter.
- `fig_sensitivity_heatmap.png` — 2D heatmap of TCI over the joint
  (growth-rate mean, w_AS) parameter space.

This requires `main.py`'s cost lookup to succeed for RSA-2048 (the driver
algorithm for all sensitivity sweeps) — it does not require `main.py` to
have been run first, since it imports `config`/`scenarios`/`simulation`
directly.

### 3. Convergence sweep

```bash
python convergence.py
```

Produces, under `./output/`:

- `convergence_sweep.csv` — mean and 95th-percentile RQR at Year 15
  (RSA-2048, quantum cost) for N ∈ {100, 200, 500, 1000, 2000, 5000, 10000}.
- `fig_convergence.png` — the convergence plot (log-scaled N on the
  x-axis) for both statistics, with the identified convergence point
  marked.
- Console output reporting the smallest N within the stated absolute
  tolerance (default 0.01 on the RQR scale) of the N=10,000 reference
  value, for that N and every larger N tested.

**Note on N=1000 vs the converged value:** the convergence sweep shows
N=1000 sits ~0.033 outside this paper's stated 0.01 tolerance on mean
RQR at Year 15, which is why `config.py`'s default is `N_ITERATIONS =
5000`, not 1000. Every headline result in the paper (`main.py`,
`run_sensitivity.py`) is generated at N=5000 for this reason — running
either script with the repository's default settings reproduces the
paper's numbers directly, no manual edit required. If you need tighter
numerical precision for a specific downstream use, N=10000 was the
convergence sweep's own reference value; edit `N_ITERATIONS` in
`config.py` accordingly.

## Reproducibility

Every numeric result in the paper is generated with a fixed random seed
(`RANDOM_SEED = 42` in `config.py`, using NumPy's `default_rng`). This
means every RQR, CAS, and TCI value, and every sensitivity/convergence
number, is **exactly** reproducible bit-for-bit across machines and
operating systems — only the wall-clock timing figure in the environment
report is hardware-dependent. If your output doesn't match the paper's
reported numbers, check that `config.py`'s parameters (especially
`GROWTH_MODEL`, `GAMMA_K`, `GAMMA_THETA`, and the values in
`ATTACK_COSTS`) haven't been modified from the defaults.

## Growth-rate model: Gamma vs. Gaussian

`config.py`'s `GROWTH_MODEL` field controls which distribution is used for
the annual capability growth rate `g`:

- `"gamma"` (**default**, used for every result in the paper) — calibrated
  against two Global Risk Institute / evolutionQ 2024 survey targets
  (5-year and 10-year crossing probabilities). Strictly positive by
  construction.
- `"gaussian"` — a Gaussian fit to the *same* two calibration targets,
  retained only for direct comparison. This fit implies roughly a 48%
  probability that adversarial capability *shrinks* over time — an
  unphysical result documented in the paper as the reason the framework
  moved to the Gamma model. Do not use this as an alternative default;
  it exists so the paper's "Discovered Problem with the Gaussian
  Assumption" section is independently checkable from this code.

## Known limitations (see also the paper's Limitations section)

- `M_KM` (key management posture) and `M_CAI` (crypto-agility index) are
  currently illustrative constants (`config.M_KM_CONSTANT = 0.85`,
  `config.M_CAI_CONSTANT = 0.75`), not values derived from any
  organization's real telemetry. Every CAS/TCI result in the paper
  inherits this simplification. `M_CAI`'s three-term definition
  (CBOM completeness, hybrid-module coverage, patch currency) is defined
  in the paper but not yet wired into `simulation.py`.
- `sigma_eps` (annual noise around the growth trend) remains an
  illustrative value; the survey data used to calibrate the growth-rate
  *trend* cannot identify year-to-year volatility.
- `alpha` (RQR logistic sharpness) is calibrated from a single assumed
  anchor point, not a documented expert elicitation — though the
  sensitivity analysis shows the output is comparatively insensitive to
  it.
- Attack costs (`config.ATTACK_COSTS`) are treated as static point
  estimates. The Kyber-512 quantum core-SVP figure in particular is
  disputed in the NIST PQC forum record.
